# 단테식 매매 파이프라인 — 검색기 포착 → 타점 → 진입 순서

> 질문: "검색기로 포착 → 타점 잡기, 어느 순서로?"
> 답: 단테는 **발굴(일봉·마감후)과 타점(분봉·장중)을 분리한 2단계 깔때기**로 운영한다.
> 근거: 유튜브 영상 08·14·16·18 (RESEARCH/dante_youtube_screener_conditions.md).
> 단테 원문 비유: *"투망을 던져 200마리를 가둔다(발굴). 그중 잡고기를 골라낸다(타점)."*

---

## 핵심 원칙 — 하나의 검색기로 둘 다 하지 않는다

| | 1단계: 발굴(포착) | 2단계: 타점 |
|---|---|---|
| **목적** | "살 만한 종목군" 추리기 | "지금 사는 자리" 포착 |
| **봉** | 일봉(EOD) + 장중 조건검색 | 분봉(5분봉) + 호가 |
| **시점** | 마감 후 **또는** 장중 실시간 | 장중 실시간 |
| **누가 실시간 담당** | **증권사 HTS 조건검색**(서버 push) | 우리 프로그램 + KIS 웹소켓 |
| **결과 규모** | 수천 → 수십 종목 | 수십 → 매수 1~3 |
| **우리 구현** | `eod_scan.py`(보조/백테스트) + **HTS 조건검색 연동(정석, 예정)** | `should_buy` 일부 + TODO |

→ **핵심 인식(2026-06 갱신)**: 장중 "전 종목 실시간 발굴"은 **개인 API로 불가**(KIS 웹소켓 동시구독 ~40종목·레이트리밋 한계). 전 종목 틱단위 스크리닝은 **증권사 서버(HTS 조건검색)만** 할 수 있다. 따라서:
> - **발굴의 실시간성 = 키움/LS HTS 조건검색이 담당** (편입/이탈 push). 우리 `eod_scan.py`는 마감 후 일봉 발굴(역배열 스윙·백테스트·튜닝)용 **보조**.
> - **우리 프로그램의 몫 = HTS가 push한 수십 종목의 타점 확정 + 자동 주문/청산**(종목 적어 KIS로 실시간 충분, 24h 무인 자동매매는 우리 코드만 가능).
>
> 상세·연동방법·증권사 비교 = `RESEARCH/realtime_screener_integration.md`

## 운영 순서 (Stage 0 → 4)

### Stage 0 — 발굴 (두 갈래)

**0-A. 일봉 발굴 (마감 후) ✅ 구현됨 — 보조/백테스트**
- **시점**: KR 15:40 KST / US 16:10 ET (스케줄러 자동)
- **실행**: `scripts/eod_scan.py` → `RESEARCH/eod/eod_{market}_{날짜}.md`
- **검색기**: breakout 세력봉(`screen`) + 단테 역배열 스윙 B-1(`screen_dante_reversal`) + 역배열 워치리스트
- **용도**: 역배열 스윙처럼 **확정 종가 기준** 발굴, 파라미터 튜닝(`screener_backtest.py`), 리서치. 장중 실시간 발굴 대체는 아님.

**0-B. 장중 실시간 발굴 ⚠️ 연동 예정 — 실전 정석**
- **방식**: 키움/LS HTS 조건검색식 → 신 WebSocket API로 **편입/이탈 push 수신**
  - 키움 `ka10171`(목록)→`ka10173`(실시간), LS `t1866`→`t1860`+`AFR`
- **맥미니 운영**: HTS 설치 불필요(신 API는 서버 직통). 조건식 **작성만** 영웅문4/LS HTS(Windows) 1회 → 서버 저장 후 API로 호출
- **산출물**: 장중 실시간 후보군 → 워치리스트로 주입 → Stage 2로
- 상세 = `RESEARCH/realtime_screener_integration.md`

### Stage 1 — 개장 전 정리 (아침)
- 워치리스트 로드 + 갭/뉴스 1차 필터 (단테: 뉴스로 이미 갭 뜬 건 제외, 재료 미노출 갭만)
- (선택) TradingAgents AI 사전분석 — 이미 08:45 KST 자동 실행됨(`USE_TA_FILTER`)
- → "오늘 감시할 N종목" 확정

### Stage 2 — 타점 포착 (장중, 분봉 실시간) ⚠️ 부분구현/TODO
**입력**: Stage 0-B의 HTS 조건검색 push로 좁혀진 워치리스트 종목**만**. 이 종목들만 KIS 웹소켓으로 정밀 감시(종목 적어 실시간 충분).
타점 판정 (단테 2차 타점식):
- 5분봉 **일목 기준선 1.5~3% 근접** (눌림 도달)
- **볼린저밴드** 근접
- **5일선 회복/근접** (오도리 자리)
- **체결강도 ≥110**, 매도/매수 **호가잔량비 ≥150%** (실시간 호가 — KIS 웹소켓)
- → 조건 충족 순간이 "타점"
- 참고: 일부 호가/체결강도 조건은 HTS 조건식(0-B)에 이미 포함시켜 1차로 거를 수도 있음 → 역할 분담은 연동 시 결정

### Stage 3 — 진입 판정 (`should_buy` 8관문) ✅ 구현됨
블랙리스트 → 직전매도가 → 킬스위치 → 시간대 → 등락률 → 검색기 → 엔진 → TA → **주문**

### Stage 4 — 청산 (`should_sell`) ✅ 구현됨
손절(단테: **돌파 기준봉 저점/5일선 이탈**) > 익절 > 트레일링

## 한 줄 요약
**전 종목 실시간 발굴은 HTS 조건검색(증권사 서버)이 담당 → push된 수십 종목을 우리 프로그램이 KIS로 타점 확정·주문.**
개인 API로 전종목 실시간 스크리닝을 이기려 하지 말 것. `eod_scan.py`(일봉 발굴)는 보조·백테스트용으로 유지하고, 다음은 **HTS 조건검색 연동 + push→타점 배선**이 남았다. 맥미니엔 HTS 설치 불필요(조건식 작성만 Windows 1회).

관련 문서: 조건식 전체 = `dante_youtube_screener_conditions.md` · 검색기 코드 = `common/screener.py` · **실시간 연동 = `realtime_screener_integration.md`**
